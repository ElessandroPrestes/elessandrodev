# QA-016 — Degradação graciosa do assistente RAG

**Escopo:** [SPEC-016](../specs/SPEC-016-degradacao-graciosa-rag.md) e [TASK-016](../tasks/TASK-016-degradacao-graciosa-rag.md).

| Verificação | Evidência |
|---|---|
| `npm test` | 57 testes passaram: 20 do cliente, 10 do prompt e 27 do Worker |
| `npm --prefix backend test` | 55 testes passaram, incluindo paridade do prompt e do retrieval |
| `npm run build` | Build do frontend concluído |
| `npm run rag:check` | Corpus e índice consistentes, com 36 chunks de 1024 dimensões |
| Warm-up local injetado | Oito perguntas geradas na primeira execução e oito hits na segunda. Os dois chips de contato foram respondidos diretamente |
| Scripts Lua | As transições do breaker, o descarte de resultados atrasados e a expiração do contador foram exercitados com Redis simulado |
| `git diff --check` | Sem erros de whitespace |

Os testes do Worker cobrem hit com cota esgotada, miss, 429, timeout, 5xx,
breaker aberto e sondagem concorrente, Redis indisponível e timeout, limite por
visitante, trechos, falha total e mensagens sem erros crus. Os cenários podem ser
executados individualmente pelo [runbook](../docs/operations.md#simulações-locais).

`npm run rag:eval` retornou `fetch failed` ao tentar consultar a API de
embeddings. O corpus, o índice e o algoritmo de ranking ficaram intactos.

**Pendências de release.** Review do PO, configuração dos secrets Upstash e
validação com o Redis e os provedores reais em ambiente publicado. O Gemma 4
26B foi validado com resposta simulada no formato de chat completions.

## Validação da branch de produção

A SPEC-016 foi aplicada separadamente sobre a `main`. Nesta base, passaram 56
testes e `npm run rag:check`. Os 55 testes do backend paralelo registrados acima
foram executados na branch de origem.
