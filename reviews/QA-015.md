### 2.7 Compose end-to-end

```bash
docker compose up -d --build
```

```text
elessandrodev-backend-1    Up (healthy)   0.0.0.0:3201->3201/tcp
elessandrodev-frontend-1   Up (healthy)   0.0.0.0:5212->8080/tcp
```

- `GET http://127.0.0.1:5212/` → 200.
- `GET http://127.0.0.1:5212/health` (proxy Nginx → backend) → 200 com
  `chunkCount: 36` e `sourceHash` consistente.
- `GET http://127.0.0.1:3201/ready` → 503 esperado sem credenciais, com
  `index: true` e demais checks falsos.

O frontend só inicia depois de o backend ficar `healthy`, conforme
`depends_on.condition: service_healthy`.

## 3. Contrato e Paridade

- Contrato `{ question, locale } → { response, sources }` preservado.
- Headers `X-Request-Id`, `X-Assistant-Stage`, `X-Assistant-Cache` e
  `X-Assistant-Provider` expostos.
- `tests/hybrid-parity.test.ts` compara o retriever Node com
  `shared/retrieval.js`.
- `tests/prompt-parity.test.ts` compara o prompt Node com `worker/prompt.js`.
- Índice lido em modo somente leitura; nenhum script de reindexação executado.

---

## 4. Segurança

- Nenhum segredo real em arquivos versionados; apenas `.env.example` e
  `secret.example.yaml` com placeholders.
- Backend e frontend rodam como usuários não-root.
- Kubernetes com `readOnlyRootFilesystem`, `drop: [ALL]`,
  `allowPrivilegeEscalation: false` e `seccompProfile: RuntimeDefault`.
- NetworkPolicy default deny com liberações explícitas.
- CORS com allowlist e 403 antes de processamento.
- Logs usam `questionHash`, sem pergunta crua, prompt ou chave.
- CI sem deploy e sem secrets de produção.

- Host e TLS do Ingress `oracle` são placeholders.
- Cache, rate limit e circuit breaker são por réplica.
- Worker de produção permanece ativo como rollback.
